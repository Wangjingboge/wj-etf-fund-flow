# 取数细节与校验

## 一、工具清单

| 用途 | 工具 | 关键点 |
|---|---|---|
| 区间份额变化 | `mcp__wind-fund-data__search_funds` | 自然语言查询，返回表格；一次约 50 行 |
| 均价 / 涨跌幅 / 简称 | `mcp__wind-fund-data__get_fund_price_indicators` | **实测单批 50 只 × 8 字段可一次返回** |
| 区间 VWAP（可选） | `mcp__wind-fund-data__get_fund_kline` | 单代码调用，用于精确口径 |

调用前先 `ToolSearch` 载入 schema，不要凭记忆拼参数。

**存盘约定**：每次工具返回的 JSON 原样存成文件（inflow.json / outflow.json / price1.json…），
再交给 `scripts/build_raw.py` 按 Wind 代码自动对齐。不要手工把 100 行数据敲进 JSON，错行风险极高。

**取数预算**（一次完整出图）：

| 场景 | 调用次数 |
|---|---|
| 当天首次跑 | 2 次份额 + 2 次行情（100 只 / 50 只一批）= 4 |
| 同一天换区间 | 2 次份额 + 0~1 次行情（价格走缓存） |
| 只改 N 或改样式 | 0 |

行情缓存交给 `scripts/price_cache.py`，它按交易日分区、只补缓存里没有的代码，并把 50 只一批切好。

## 二、search_funds 查询话术

### 单日（"昨天"）

```
筛选2026年10月22日场内流通份额增加最多的50只股票型ETF
筛选2026年10月22日场内流通份额减少最多的50只股票型ETF
```

返回列：
`Wind代码 | 证券简称 | 场内流通份额 | ETF一级投资范围分类 | 基金分类 | {日期}的场内流通份额 | {日期}前一交易日的场内流通份额 | {日期}场内流通份额变化`

### 区间（近一周 / 近一月 / 今年 / 自定义）

```
筛选2026年10月16日至2026年10月23日区间内场内流通份额增加最多的50只股票型ETF
筛选2026年10月16日至2026年10月23日区间内场内流通份额减少最多的50只股票型ETF
```

返回列：
`... | {起始日}的场内流通份额 | {结束日}的场内流通份额 | {起始日}至{结束日}区间内场内流通份额变化`

**基数是起始日收盘后份额**。要覆盖 N 个交易日的完整变化，起始日应取「目标区间开始日的**前一交易日**」。例如统计 10/19–10/23 这一周，起始日写 10/16（上周五）。

### 返回条数

- 单侧大约返回 50 行，够覆盖 top15–top30
- 想要 N > 50 时，说明数据源限制，不能硬凑
- 返回里偶尔混入反方向的行（含负值），本地按符号分流即可

## 三、行情指标字段

**一次把 5 个涨跌幅全取回来**，换周期时就不用再调接口：

```
中文简称,最新交易日,最新均价,涨跌幅,5日涨跌幅,20日涨跌幅,60日涨跌幅,年初至今涨跌幅
```

- `最新均价`：该交易日全天成交均价，是折算金额的默认价格
- 实测 **50 只 × 上面 8 个字段**一次返回正常，100 只只需 2 批
- 支持一次传多代码，返回顺序与传入顺序一致
- 代码无效时整批可能报"未识别到有效的金融标的:XXXX；相近证券：..."，把该代码剔除后重试剩余部分
- 部分新代码（158xxx 等）的 20 日/60 日/年初至今字段可能是 null，属正常，图上显示 "-"

## 四、精确 VWAP（可选口径）

默认用最后一日均价近似。区间越长、价格波动越大，误差越大。需要精确时：

```
get_fund_kline(windcode, begin_date, end_date, period=10)  # 日K
```

对区间内每日 `成交额 / 成交量` 求加权：
```
VWAP = Σ成交额 / Σ成交量
```
30 只标的要调 30 次，只在用户明确要求"精确"时才做，并在图注写明"按区间成交额加权均价计算"。

## 五、常见坑

1. **份额变化排名 ≠ 金额排名**。份额单位是"份"，各 ETF 净值差异巨大（0.3 元 vs 6.7 元），必须乘均价再排序。
2. **跨境 / 商品 ETF 不算股票型**。恒生科技、黄金、原油 ETF 会被 `股票型ETF` 分类过滤掉，这符合口径；如果用户要"含跨境的全部 ETF"，查询里改成"ETF"并单独标注。
3. **ETF 代码格式**。沪深 ETF 是 `510xxx/512xxx/515xxx/516xxx/56xxxx/58xxxx.SH`、`159xxx.SZ`，另有少量 `158xxx.SZ` 新代码，部分工具不认，剔除即可。
4. **不要把"主力净流入"当成资金流入**。东方财富的"主力资金净流入"是按成交单笔金额统计的二级市场博弈数据，与 ETF 申赎净流入完全不是一个东西，混用会被懂行的人一眼看穿。
5. **媒体口径可能相反**。同一交易日，按"区间成交均价 × 份额变化"多数口径是净流入，而按"区间内每日净流入累加"可能得到净流出的反向结论。选一种口径贯穿到底，并在图注写明，不要两个口径混着写。
6. **周末与节假日**。"昨天"在周一要回退到上周五，遇长假要跳过节假日期。用 `date` 命令推算后，**用 Wind 返回列名里的实际日期反查**，不要依赖自建的交易日历。
